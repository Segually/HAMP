# Client diff: 200597 → 200613 (what the dev stripped)

Goal: find game-code the dev removed between the last public-server-era
client (200597) and the stripped current client (200613), to know what
HAModHelper must re-implement.

**Method.** Two arm64 IDA databases (Redux-named): 200597 from the
dev-uploaded arm64 split XAPK, 200613 from the existing DB. Compared by
(a) `switch`-case sets *within* `GameServerReceiver$$OnReceive` /
`FriendServerReceiver$$OnReceive` (reliable — structural within one
function), and (b) game-class method-name set subtraction (noisy — the two
DBs are named by different tooling, so inlining/refactor/rename masquerade as
removal). Every set-diff candidate below was **verified individually** in the
200613 DB, not trusted from subtraction.

Decomp exports: `docs/decomp/HA_200597/` (v597_* = 200597, v613_* = 200613).

---

## Confirmed real removals

### 1. `CustomTeleporterControl::LayoutAsPublicServer`  — the significant one
Surgically deleted (every other `CustomTeleporterControl` method survives).
In 200597 it re-skins the teleporter window for public-server context:
- show `miniwindow_header_L_bg`, hide `miniwindow_header_R_bg`
- set left header text to **"Player Portals"**
- `inventory_ctr.LayOutCraftingTab(normal)` + activate its tab object
- enable `tele_search_button`

Called from four teleporter methods that **all still exist in 200613** but no
longer make the call: `OnLeftMiniwindowTabPressed`, `PressAcceptEditTeleporter`,
`PressBackOnTeleSearch`, `InteractWithTeleporter`. So on a HAMP/public server
the 200613 teleporter window renders in plain single-player layout.
**RESTORED in HAModHelper** `PublicServer/` folder (2026-06-10, builds clean):
`PublicServerLayout.Apply()` reproduces the re-skin with named interop members,
postfixed onto those four methods, gated on `NetworkManager.IsHampServer`.

### 1b. The wider `is_public_server` surface (the field itself is gone in 200613)
`GameServerConnector.is_public_server` (200597 offset 0x39; that slot is
`pvp_enabled` in 200613) gated SIX behaviors, all stripped. Found by scanning
765 gameplay/UI function decompilations for field reads:

| 200597 method | public-server behavior removed |
|---|---|
| `CustomTeleporterControl::LayoutAsPublicServer` (3 callers) | the teleporter re-skin above (**restored**) |
| `CustomTeleporterControl::ShouldDisableTeleporterButton` | teleporter button never disabled on a public server |
| `inventory_ctr::do_option` | non-moderators blocked from placing: "Cannot place / You are not a moderator" (client-side build-permission gate — pairs with HAMP admins) |
| `FriendServerSender::PackWorldString` | different world-identity byte packed when not public-server (host=2 / guest=3) |
| `FriendServerInterface::CreateChatLogObj` | chat-log lines render differently on a public server |
| `inventory_ctr::crafting_inc_page` | teleporter-tab paging differs |

Only `LayoutAsPublicServer` is restored so far; the other five are documented
candidates (see HAModHelper `PublicServer/README.md`). The `do_option`
moderator-placement gate is the most HAMP-relevant.

### 2. C→S `0x2C` — `GameServerSender::SendDeleteFurnitureFile(InventoryItem)`
Gone (verified absent in 200613; no `delete_furniture*` symbol remains).
Told the server to delete a furniture piece's separate save file. 200613
removes furniture via `0x21 SendRemoveObject` but no longer sends the file
deletion. Impact for HAMP: orphaned furniture-content files may accumulate
server-side. Cheap fix server-side (clean up on 0x21) or mod re-sends 0x2C.

### 3. C→S `0x5B` — `GameServerSender::SendWitnessedRespawnExpire()`
Gone (verified). Minor respawn-sync packet (a witnessed respawn expiring).
Low priority; note it exists and move on.

### 4. Worldgen offload — `GameServerReceiver$$OnReceive` cases 0x0E/0x0F/0x10
       + `GameServerSender::SendGeneratedChunk`
The old "server asks client to generate a chunk/biome/cave and send it back"
flow. **REJECTED for restoration** — trusting a client to produce world data
is an anti-cheat disaster. All the generators it called still exist in 200613
(`ChunkGenerator*$$GenerateUnexplored`, etc.) but we are NOT re-enabling this.
Documented here only so it's not re-investigated.

### 5. Save-format migration cruft (real but irrelevant)
`ConverterMerchants`, `ConverterFloors`, `ConverterMPRewrite` (the v2→v3
"Multiplayer Rewrite" save converter), `ConverterNavposts`,
`ConverterPaintbrushes`, `ConverterCreatureIds`, `OldSingleFile_3`. One-time
migrators for ancient local saves. Nothing to restore.

## NOT removed (set-diff false positives — refactored/inlined)
- **`ItemScreenshotTaker`** — *rewritten*, not removed. 200597 did pixel
  manipulation (`CalcPixel`/`OverlayColors`/`ApplyOutlineAndGlow`); 200613
  does camera-based capture (`PositionCamera`/`InstantiateObjectForScreenshot`/
  `TakeParticlesScreenshot`, `screenshot_pair` struct). Modded-item thumbnails
  go through the new path.
- `CreatureStruct::Generate*`, `Combatant::DropCoins/SpawnRandomDrop`,
  `LootControl::Get*`, `ChunkControl::Round`, `GraphicsControl::*`,
  `AdvertControl::*` — features all present; inlined or renamed.

## Fully intact (no action)
- **Friend-server side**: `FriendServerReceiver$$OnReceive` case set is
  *identical* (43 cases) between versions; every `FriendServerInterface`
  public-server method survives byte-for-byte size
  (`PressPubServerTab`, `RedrawPublicServerList`, `RedrawJoinPubServScreen`,
  `PressJoinPublicServer`, paging) plus `FriendServerSender::{RequestPublicServerList,
  TryJoinPublicServer}`. The browser flow works; only the *tab* is hidden via
  `HideMiniwindowHeaders`, already un-hidden by the mod's `RestoreServerListTabPatch`.

  (BANDIT_CAMP_CLEARED). Otherwise identical.
- FriendServer: identical.
